# order:lock:{order_no} — 订单创建并发锁

## 基本信息

| 字段 | 值 |
|------|-----|
| 存储类型 | Redis |
| 模块 | logistics-order |
| Key 模式 | `order:lock:{order_no}` |
| Value 类型 | String（锁持有者 request_id） |
| TTL | 30s（防死锁） |
| 负责人 | 后端开发 |
| 需求来源 | REQ-LO-001 (TP-LO-001-07) |
| 版本 | v1.0 |

## 写入场景

| 触发接口 | 操作 | Key 示例 | 业务规则 |
|---------|------|---------|---------|
| POST /orders | SET NX EX 30 | `order:lock:LO-20260417-0001` | 生成订单号后立即加锁；SET NX 失败则返回 400 "请勿重复提交" |
| POST /orders（完成/失败后） | DEL | `order:lock:LO-20260417-0001` | 无论成功失败都释放锁（finally 块） |

## 读取场景

无直接读取。锁的存在性通过 SET NX 的返回值隐式判断。

## 过期/清理策略

| 策略 | 说明 |
|------|------|
| TTL 过期 | 30s 自动过期，防止异常退出导致死锁 |
| 主动删除 | POST /orders 完成后 DEL |

## 关联其他存储

| 存储节点 | 类型 | 关系 | 说明 |
|---------|------|------|------|
| t_order | 数据库 | 锁保护的写入目标 | 锁存在期间才允许写入 t_order |
